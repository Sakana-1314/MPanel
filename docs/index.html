MPanel服务器管理面板文档

web/panel、core、agent 三端分离；沿用 1Panel 的 /opt/mpanel 与 systemd 约定；站点管理用 Caddy。

从源码安装
与 1Panel 的差异

三端分离

web/panel 只负责界面；core 负责登录、机器注册、隧道与代理；agent 在目标主机执行站点、数据库、容器、文件、终端与计划任务。

1Panel 风格部署

安装根 /opt/mpanel，配置 conf/app.yaml 与 conf/agent.yaml，二进制放在 /usr/local/bin，服务用 mpanel-core.service / mpanel-agent.service。

Caddy 容器化

Caddy 以 mpanel-caddy 编排运行，站点页一键安装；每站点生成 sites.d/*.caddy，apply 在容器内 validate → 备份 → 原子替换 → reload → 回滚。

长任务不阻塞

站点应用、编排启停、镜像拉取等耗时操作转为后台任务，立即返回 202；进度弹窗与任务中心展示状态、日志与结果。

能力缺失可降级

没有 Caddy 容器、Docker、PostgreSQL 客户端、Redis 客户端或 PTY 时进程照常启动；列表返回 available=false，写操作返回 UNAVAILABLE 与可执行提示。

一句话定位 ​

MPanel 是一个三端分离的服务器管理面板：web/panel 是 Vue 3 + Vite + Vue Router + Naive UI 单页前端，core 是控制面（登录、机器注册、健康检查、隧道与 REST/WS 代理），agent 是功能面（在每台被管主机上执行站点、证书、数据库、容器、文件、终端与计划任务）。面板只连接 core，不直连 agent；每台机器的页面以独立标签页打开，多台机器的页面可以同时混合管理工作。

与 1Panel 的取舍 ​

沿用 1Panel 的部署约定 ​

MPanel 刻意保持 1Panel 用户熟悉的路径与进程模型：

项目1PanelMPanel
安装根/opt/1panel/opt/mpanel
配置conf/app.yamlconf/app.yaml（core）、conf/agent.yaml（agent）
数据 / 日志 / 数据库 / 备份data/、log/、db/、backup/data/、log/、db/、backup/，另有 tmp/
二进制/usr/local/bin/1panel-core、1panel-agent/usr/local/bin/mpanel-core、mpanel-agent、mpctl
systemd 服务1panel-core.service、1panel-agent.servicempanel-core.service、mpanel-agent.service
控制命令1pctlmpctl（/usr/bin/mpctl 软链）

这意味着备份、迁移、权限与 SELinux 的处理方式基本可以照搬 1Panel 的经验，运维不需要学习一套新目录。

网站管理改用 Caddy ​

1Panel 用 nginx 管理网站；MPanel 用 Caddy，原因不是偏好，而是站点模型更简单可靠：

  1. Caddyfile 片段化：每个站点生成一个 sites.d/<siteId>.caddy 片段，主 Caddyfile 只有 import sites.d/*.caddy。增删站点是增删文件，不需要在一个大配置里做文本手术。
  2. 自动 HTTPS：域名只要解析到本机，Caddy 默认自动申请和续期证书；tls internal、tls off 只是配置项，不需要额外维护 certbot 与续期定时任务。
  3. validate / reload / 回滚是内建流程：apply 前先 caddy validate，通过后备份现有目录、原子替换、caddy reload；reload 失败自动恢复备份并再次 reload。整个过程可以给出明确的 stage 与 caddyOutput。
  4. 结构化配置边界更清晰：MPanel 只接受结构化站点配置，不支持粘贴原始 Caddyfile 片段；所有进入 Caddyfile 的字符串都经过校验与转义，避免 nginx 时代常见的配置注入与手写错误。

文档地图 ​

  • 从源码安装：构建、放置二进制、systemd 单元、首次启动 bootstrap token。
  • 配置文件与环境变量：/opt/mpanel 目录树、app.yaml 与 agent.yaml 全部字段、MPANEL_* 覆盖规则。
  • 生产部署：反向代理（Caddy / nginx）、升级、备份、SELinux 与权限。
  • 站点与 Caddy：站点模型、apply 流程、证书扫描。
  • 数据库与 dbx：PostgreSQL / Redis 档案、备份恢复、dbx iframe 与 handoff。
  • 边缘节点：入网密钥、快照、离线作业。
  • REST API 契约：所有端点、请求/响应形状与错误码。
  • 隧道协议：stdio / reverse-ws 的帧格式、分块与多路复用。
  • 故障排查：机器离线、Caddy apply 失败、PTY、dbx、入网 403。
