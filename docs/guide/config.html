配置文件与环境变量 ​

MPanel 的配置完全沿用 1Panel 的目录与文件名：安装根默认 /opt/mpanel，core 读 conf/app.yaml，agent 读 conf/agent.yaml。所有字段都可以用 MPANEL_* 环境变量覆盖，便于容器、CI 与 systemd 部署。

实现状态

配置加载、默认值、目录创建、原子写回与环境变量覆盖由 server/core/config 实现（已实现）。本文列出的字段与该包的结构体一一对应；ssl、entrance、username、password 等字段目前只做加载与持久化，具体生效逻辑随 core 启动流程落地。

1. 目录树 ​

Linux 上默认安装根为 /opt/mpanel；非 Linux 开发机回退到 ~/.mpanel，便于非特权进程启动。core 与 agent 共用同一安装根，但使用不同配置文件与子目录。

text
/opt/mpanel/
├─ conf/
│  ├─ app.yaml            # core 配置（0600）
│  ├─ agent.yaml          # agent 配置（0600）
│  └─ bootstrap-token     # 首次初始化用，完成后删除
├─ data/
│  ├─ agent/              # agent 状态（sites.json、databases.json、jobs、tasks、trash）
│  ├─ apps/               # 一键安装应用数据（对应 1Panel 的 data/apps）
│  │  ├─ caddy/           # 宿主 Caddy 配置，容器挂载到 /etc/caddy
│  │  │  ├─ Caddyfile
│  │  │  ├─ sites.d/*.caddy
│  │  │  └─ data/         # Caddy 证书与数据，容器挂载到 /data
│  │  ├─ postgres/
│  │  └─ redis/
│  ├─ compose/            # Docker Compose 编排（mpanel-caddy、mpanel-postgres…）
│  ├─ files/              # 默认文件管理根（files_roots 的默认项）
│  └─ sites/              # 默认站点根
├─ db/                    # 控制面状态文档（system.db_path）
├─ log/                   # 运行日志（system.log_path / agent.log_path）
├─ backup/                # 备份根（site/数据库/回滚副本）
│  ├─ caddy/
│  └─ databases/
├─ runtime/               # 运行时文件（socket、pid、临时状态）
├─ tmp/                   # 临时文件（system.tmp_dir）
└─ web/                   # 面板前端产物（system.web_dir）

说明：

  • data/、log/、db/、backup/、tmp/、web/ 在 app.yaml 中有独立字段，可以分别指向不同磁盘。
  • 默认布局对齐 1Panel：面板状态在 db/，应用数据在 data/apps/，编排在 data/compose/，站点根在 data/sites/，备份在 backup/。
  • db/ 是 1Panel 同名目录。1Panel 在这里放 SQLite 的 core.db；MPanel 的控制面使用原子 JSON 文档（server/core/store），按 1Panel 习惯放在同一棵树里，备份时直接打包整个 db/。
  • agent 的 Caddy 目录解析顺序：caddy_config 非空则用它，否则 ${base_dir}/data/apps/caddy；caddy_data 非空则用它，否则 ${caddy_config}/data。日志固定写到 ${base_dir}/log/caddy。三者分别挂载到容器 /etc/caddy、/data 与 /var/log/caddy；caddy_bin 已弃用，Caddy 只以容器运行。升级前的 ${agent.data_dir}/caddy 仍会被识别。
  • 升级兼容：旧 ${agent.data_dir}/caddy、${agent.data_dir}/sites、${agent.data_dir}/stacks 在新目录不存在时继续沿用，已有部署不会因目录调整失效。
  • 目录创建权限：core 的 conf/、data/、log/、db/、backup/、tmp/、runtime/ 为 0700；agent 的目录为 0755（站点/文件根需要被 Web 服务器读取），配置文件统一 0600。

2.1 system 字段 ​

字段类型默认值对应 1Panel说明
portint10086system.portcore 监听端口。1Panel 安装时随机取 10000–65535；MPanel 固定 10086，便于反代与防火墙预设
bindAddressstring0.0.0.0system.bindAddress监听地址。生产建议 127.0.0.1，由反向代理对外
sslstring空system.ssl预留的 TLS 开关字段，当前只加载/持久化
base_dirstring/opt/mpanelsystem.base_dir安装根。非 Linux 默认 ~/.mpanel
data_dirstring${base_dir}/datasystem.data_dir数据根
log_pathstring${base_dir}/logsystem.log_path日志目录
db_filestringcore.db—数据文件名，1Panel 兼容命名
db_pathstring${base_dir}/dbsystem.db_path状态文档目录
backupstring${base_dir}/backupsystem.backup备份根
tmp_dirstring${base_dir}/tmp—临时目录
usernamestring空—可选的管理员种子用户名；当前只加载/持久化，初始化请用 bootstrap token
passwordstring空—可选的管理员种子密码；同上
secretstring随机 32 字节—core 内部密钥，URL-safe base64；为空时自动生成
versionstring构建版本—版本号，可用 -ldflags 注入；启动时以二进制版本为准，配置里的旧值会被覆盖
entrancestring空system.entrance预留的安全入口字段，当前只加载/持久化
languagestringzh—默认语言
cors_originsstring空（允许任意来源）—收紧跨域来源时填写逗号分隔白名单（https://panel.example.com,https://ui.example.com）。留空或 * 表示允许任意来源
cors_vary_originboolfalse—默认回 Access-Control-Allow-Origin: *。开启后按请求的 Origin 回显并加 Vary: Origin，用于前置缓存必须按来源分片的部署

跨域策略 ​

面板只用 Authorization: Bearer <JWT> 鉴权，不使用 Cookie，浏览器不会自动携带任何凭据。因此默认允许任意来源：第三方页面即使发起请求，没有 token 也只能拿到 401，无法以访问者身份读取面板数据。这样静态站、桌面壳和第三方集成都能直接调用接口，无需逐个加白名单。

响应固定包含：

text
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET,POST,PUT,PATCH,DELETE,OPTIONS
Access-Control-Allow-Headers: Authorization,Content-Type,X-MPanel-Token,X-Requested-With,X-Request-Id
Access-Control-Max-Age: 600
1
2
3
4

不发送 Access-Control-Allow-Credentials —— 携带凭据的跨源请求会被浏览器拒绝，这与「不使用 Cookie」保持一致。

需要收紧时配置 cors_origins，命中名单的来源按来源回显，其它来源不返回 CORS 头。/ws 不经过 CORS 头，但按同一份白名单校验 Origin（默认放行；agent 与脚本客户端不带 Origin，不受影响），且连接本身仍要求一次性 ticket 或 Bearer。

3.1 agent 字段 ​

字段类型默认值说明
transportstringhttphttp、stdio 或 reverse-ws。stdio 由 core 拉起子进程；reverse-ws 由 agent 主动拨号 core
listenstring0.0.0.0:10087http 传输的监听地址（host:port）。reverse-ws/stdio 仍会开一个仅 loopback 的随机端口供隧道回环使用
tokenstring空agent 静态访问令牌。http 传输必填，建议至少 32 字节随机；core 用同一个值访问 agent
core_urlstring空reverse-ws/边缘节点的 core 基地址，如 https://panel.example.com；也接受完整 wss://.../ws/worker
machine_idstring空预建 reverse-ws 机器的 id；与 machine_secret 配对使用
machine_secretstring空预建 reverse-ws 机器的注册 secret，只在创建/轮换时显示一次
edge_keystring空边缘入网密钥（mpedge_...）。配置后 agent 先入网换取身份，再拨 /ws/worker
base_dirstring/opt/mpanel安装根
data_dirstring${base_dir}/data/agentagent 数据根
log_pathstring${base_dir}/log日志目录
versionstring构建版本版本号；启动时以二进制版本为准，配置里的旧值会被覆盖
caddy_binstringcaddy已弃用：Caddy 只以容器运行，该字段保留仅为兼容旧配置，agent 不读取
caddy_configstring${base_dir}/data/apps/caddy宿主受管 Caddy 配置目录（Caddyfile、sites.d/），挂载到容器 /etc/caddy；旧 ${data_dir}/caddy 仍兼容
caddy_datastring${caddy_config}/data宿主 Caddy 数据目录（证书扫描来源），挂载到容器 /data
caddy_adminstring空写入主 Caddyfile 的 容器内 admin 地址；留空用 127.0.0.1:2019，通配地址会收敛到回环
docker_binstringdockerDocker CLI 路径
docker_configstring/etc/docker/daemon.jsonDocker daemon 配置路径；容器配置页读取/写入该文件，rootless 部署改为 ~/.config/docker/daemon.json
pg_dump_binstringpg_dumpPostgreSQL 备份工具
psql_binstringpsqlPostgreSQL 恢复/查询工具
redis_cli_binstringredis-cliRedis CLI，用于 rdb 备份
files_rootslistfiles=/opt/mpanel/data/files文件管理沙箱根列表，每项 {name, path}；名称唯一，路径必须是绝对路径
log.levelstringinfo日志级别

3.2 files_roots 的两种写法 ​

YAML：

yaml
agent:
  files_roots:
    - name: files
      path: /opt/mpanel/data/files
    - name: www
      path: /var/www

环境变量（会整体替换列表）：

bash
export MPANEL_FILES_ROOTS='files=/opt/mpanel/data/files,www=/var/www'

解析规则：逗号分隔，每项 name=path；没有 = 时名称默认为 files；名称或路径为空则跳过。

4. MPANEL_* 覆盖规则 ​

4.1 优先级与写回 ​

加载顺序固定为：

text
内置默认值  →  conf/app.yaml 或 conf/agent.yaml  →  MPANEL_* 环境变量
1
  • 环境变量只覆盖非空值；无法用空字符串清空 YAML 中的字段。
  • MPANEL_PORT 只有在解析为 1..65535 的整数时才生效，非法值被忽略。
  • 每次加载都会做归一化，并把结果原子写回 YAML（0600）。因此环境变量覆盖过的值会落盘：之后即使不再设置该环境变量，文件里仍然是上次覆盖后的值。需要恢复默认值时请手动编辑 YAML。
  • 安装根优先取 MPANEL_BASE_DIR（core）或 MPANEL_AGENT_BASE_DIR（agent）；配置文件路径由安装根推导，不能用环境变量单独指定文件名。

5. 端口与监听建议 ​

场景coreagent
脚本/第三方客户端直连（面板不采用）不启动127.0.0.1:10087 + 同机反代
面板 + 多机（http 传输）127.0.0.1:10086 + 反代0.0.0.0:10087 仅内网可达
面板 + 多机（reverse-ws / 边缘）127.0.0.1:10086 + 反代listen 不对外；agent 只发起出站连接

web/panel 只连接 core：浏览器不保存 agent token，也不直接访问 agent 的 10087 端口。

修改端口后要同步更新反向代理、防火墙与前端连接地址。配置生效需要重启对应进程；环境变量在进程启动时读取。
