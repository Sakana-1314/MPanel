从源码安装 ​

本页描述把 MPanel 安装到一台 Linux 主机的目标流程：从源码构建 Go 二进制，放到 /usr/local/bin，用 systemd 托管 mpanel-core 与 mpanel-agent，完成首次初始化后通过浏览器访问。

实现状态

Go 重写已落地：server/cmd/、server/core/、server/agent/ 与全部业务模块均可构建，go build ./...、go vet ./...、go test ./... 在 CI 中作为合并门禁。以下命令均可直接执行。已实现与规划中的完整清单见首页。

1. 前置条件 ​

  • Linux（amd64 或 arm64），systemd 作为服务管理器。
  • Go 工具链版本不低于仓库 go.mod 的 go 指令（当前为 1.27.2）。
  • 一个专用系统用户（下文用 mpanel），不要用 root 直接运行面板进程。
  • 可选外部能力：Docker Engine 与 Compose v2（容器/编排；站点的 Caddy 也以容器部署）、PostgreSQL 客户端工具（pg_dump、psql）、Redis 客户端（redis-cli）。缺少这些不会阻止 agent 启动，只影响对应模块的写操作。Caddy 不需要在宿主机安装二进制。

端口约定：

进程默认监听用途
mpanel-core0.0.0.0:10086控制面 API、登录、机器代理，可托管 web/panel 静态文件
mpanel-agent0.0.0.0:10087agent API；被 core 以 http 传输管理时只对 core/内网开放。面板不直连此端口

生产环境不要让 10086/10087 直接暴露公网，统一由反向代理终止 TLS，见生产部署。

2.1 使用 CI 成品（测试机） ​

main 每次更新后，构建成品 工作流会删除旧的 dev Release 并重新发布，产物为：

资产内容
mpanel-linux-amd64.tar.gzmpanel-core、mpanel-agent、mpctl、web/ 面板产物与同源 store/、LICENSE
mpanel-linux-arm64.tar.gz同上，ARM64
SHA256SUMS两个压缩包的 SHA-256

下载并部署到测试机：

bash
set -euo pipefail
case "$(uname -m)" in
  x86_64|amd64) arch=amd64 ;;
  aarch64|arm64) arch=arm64 ;;
  *) echo "不支持的架构: $(uname -m)"; exit 1 ;;
esac

gh release download dev --repo Sakana-1314/MPanel \
  --pattern "mpanel-linux-${arch}.tar.gz" --pattern SHA256SUMS --clobber
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf "mpanel-linux-${arch}.tar.gz"

sudo install -m 0755 "mpanel-linux-${arch}"/mpanel-core \
  "mpanel-linux-${arch}"/mpanel-agent "mpanel-linux-${arch}"/mpctl /usr/local/bin/
sudo rm -rf /opt/mpanel/web
sudo install -d -o mpanel -g mpanel -m 0755 /opt/mpanel/web
sudo cp -R "mpanel-linux-${arch}/web/." /opt/mpanel/web/
sudo systemctl restart mpanel-core mpanel-agent

mpanel-core version
mpanel-agent version

首次启动时 server/core/config 会在配置缺失时按默认值创建 conf/app.yaml 与 conf/agent.yaml，权限 0600；conf/ 目录权限为 0700。

5. 首次启动与 bootstrap token ​

core 首次启动时如果还没有管理员账号，会生成一次性 bootstrap token：

  • 写入 /opt/mpanel/conf/bootstrap-token，权限 0600；
  • 同时打印到启动日志（journalctl -u mpanel-core 可见）；
  • token 只用于初始化，设置完用户名/密码后失效并删除文件。

初始化流程：

  1. 读取 token：

    bash
    sudo cat /opt/mpanel/conf/bootstrap-token
    1

  2. 调用初始化端点设置管理员账号（POST /api/v1/auth/setup，字段以 server/core/auth 落地为准）：

    bash
    curl -sS -X POST http://127.0.0.1:10086/api/v1/auth/setup \
  -H 'content-type: application/json' \
  -d '{"token":"<bootstrap-token>","username":"admin","password":"<至少 10 位密码>"}'
    1
    2
    3

  3. 成功后删除 conf/bootstrap-token（若进程未自动删除），用新账号登录。

如果 token 泄漏或过期：在仍无管理员账号的前提下删除 conf/bootstrap-token 并重启 core，会重新生成。

agent 没有用户名密码，也没有匿名模式。它只接受静态 token：

  • 配置项 agent.token，或环境变量 MPANEL_AGENT_TOKEN；
  • 建议至少 32 字节随机值；
  • curl 调用使用 Authorization: Bearer <token> 或 X-MPanel-Token: <token>；
  • 直连模式的前端连接页填同一个 token。

生成随机 token：

bash
openssl rand -base64 48
1

/healthz 只表示进程可响应，能力状态看 GET /api/v1/system/info。

访问方式：

  • core 模式：浏览器打开 http://<服务器IP>:10086。core 托管 web/panel 静态文件（规划中）；若未托管，用 Caddy/nginx 把面板静态目录与 /api/v1、/ws 反代到 core。
  • agent 直连模式：浏览器打开面板静态站点，在「新增连接」中选择 agent（直连 token），地址填 http://<IP>:10087，token 填 MPANEL_AGENT_TOKEN。单机模式没有 /machines* 与 /system/overview，这是预期行为。
  • 生产环境务必改为 HTTPS 域名访问，见生产部署。

7. 升级与卸载 ​

升级只替换二进制，不移动 /opt/mpanel：

bash
sudo systemctl stop mpanel-agent mpanel-core
sudo install -m 0755 mpanel-core mpanel-agent mpctl /usr/local/bin/
sudo systemctl daemon-reload
sudo systemctl start mpanel-core
sudo systemctl start mpanel-agent
1
2
3
4
5

升级前先备份 /opt/mpanel（至少 conf/、data/、db/、backup/），因为配置里包含会话密钥、机器凭据与数据库密码密文。详见生产部署。

卸载：

bash
sudo systemctl disable --now mpanel-agent mpanel-core
sudo rm -f /etc/systemd/system/mpanel-core.service /etc/systemd/system/mpanel-agent.service
sudo systemctl daemon-reload
sudo rm -f /usr/local/bin/mpanel-core /usr/local/bin/mpanel-agent /usr/local/bin/mpctl /usr/bin/mpctl /usr/bin/mpanel
# /opt/mpanel 含配置与数据，确认不再需要后再删除
